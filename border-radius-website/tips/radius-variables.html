Type a radius once, reuse it everywhere

Tip 01 · 2 min read · updated June 2026

If you’ve ever set a corner to 8 on one card and 10 on the next without meaning to, this one’s for you. The fix is the feature this whole newsletter is named after: stop typing radius values by hand and store them as number variables instead.

Why eyeballing corners hurts

A raw value like 8px tells you nothing about intent. Is this a small corner or a medium one? Should it match the button next to it? Six months and three contributors later, a file full of hand-typed radii drifts — and “tighten the corners a touch” becomes an afternoon of hunting.

A variable like radius/md carries the intent and the value. Change your mind once, and every corner bound to it moves together.

Set it up in four steps

  1. Open the Variables panel (the small grid icon in the right sidebar, or via Local variables).
  2. Make a collection called radius and add number variables: sm = 4, md = 8, lg = 16, full = 999.
  3. Select a frame, and in the corner-radius field click the variables icon to bind it to radius/md instead of a literal number.
  4. Build your components against those tokens. Buttons, cards, inputs, chips — all pointing at the same handful of values.

Then map it to code

Because they’re named tokens, Dev Mode can hand engineers radius/md instead of a bare 8px. If your codebase has matching tokens, the handoff stops being a game of “what number was that” and starts being copy-paste.

Rule of thumb: if you’ve typed the same radius value twice, it should probably be a variable. Same goes for spacing — see picking a spacing scale.

That’s the whole trick. Five minutes of setup, and your corners stay honest for the life of the file.
